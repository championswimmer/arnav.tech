# Tag pages & tag links

Add topical **tags** across essays, posts, and projects, with per-tag listing
pages at `/tags/{tag}` and clickable tag links at the top of each piece.

- [x] Add a `tagSlug()` normalizer + `getTaggedEntries()` helper in `src/lib/tags.ts`
- [x] Build the dynamic route `src/pages/tags/[tag].astro` (getStaticPaths + listing)
- [x] Add a `/tags` index page listing every tag with counts
- [x] Turn tag chips in `PostMeta.astro` into links to `/tags/{tag}`

- [x] Verify with `bun run build` (all tag routes generate, no broken links)

## Context

The three written collections — `essays`, `posts`, `projects` — already declare
`tags: z.array(z.string()).default([])` in `src/content.config.ts`, so **no
schema change is needed**. Slides have no tags and are out of scope.

Today tags only appear in two places:

- `PostMeta.astro` renders them as plain `#tag` chips (used by `PostLayout`).
- `EssayLayout` and `ProjectLayout` pass `tags` to `BaseHead` for
  `<meta property="article:tag">` but **do not display them** to readers.

There is also a reserved set of **AI-usage tags** — `ai-free`, `ai-assisted`,
`ai-generated` (defined inline in `EssayLayout.astro` / `PostLayout.astro`).
These are rendered as a badge via the `AiUsage` component, not as topical tags,
so they must be filtered out of tag links, tag pages, and the tag index.

URL note: the request mentioned both `/tag/{tagname}` and `/tags/authentication`;
this plan standardizes on the plural **`/tags/{tag}`** to match the concrete
example. Adjust if the singular form is preferred.

## Notes

**1. `src/lib/tags.ts` (new shared helper)**

- `tagSlug(tag: string)` — lowercase, trim, collapse whitespace/`/` to `-` so a
  tag like `Web Auth` maps to `web-auth` in the URL. Mirror the existing
  `cleanSlug` style in `src/lib/slug.ts`.
- Export `AI_USAGE_TAGS` here as the single source of truth and have
  `EssayLayout`/`PostLayout` import it instead of redefining it inline.
- `isTopicalTag(tag)` — `!AI_USAGE_TAGS.includes(tag)`.
- `getTaggedEntries()` — `getCollection` over `essays`, `posts`, `projects`
  (filtering `!data.draft`), returning a normalized shape
  `{ href, title, description, pubDate, heroImage, collection, tags }` reusing
  the `href` conventions already in each `index.astro` (`cleanSlug(id)`).
- `getAllTags()` — build a `Map<slug, { label, count, entries }>` from the above,
  skipping non-topical tags; used by both the index and `getStaticPaths`.

**2. `src/pages/tags/[tag].astro` (new dynamic route)**

- `getStaticPaths()` returns one path per topical tag slug, passing the matching
  entries as `props`.
- Render inside `BaseLayout` with the same `page-head` kicker/blurb pattern as
  `essays/index.astro`, e.g. kicker `#{tag}` and a count blurb.
- Reuse `EntryList` for the results. `EntryList`'s `variant` is essay-vs-tech;
  a tag page mixes collections, so default to `variant="tech"` (or split into
  sections per collection — optional refinement).

**3. `src/pages/tags/index.astro` (new)**

- A simple tag cloud / list from `getAllTags()`, each linking to `/tags/{slug}`
  with its count. Do **not** add a `Tags` entry to `NAV_LINKS` — leave the nav
  untouched; the index is reachable via tag links only.

**4. Linking tags in the UI**

- `PostMeta.astro`: wrap each `#{tag}` in `<a href={`/tags/${tagSlug(tag)}`}>`,
  filtering with `isTopicalTag`. Keep the `.tag` accent styling; add hover.
- Essays/projects currently hide tags. Either add `<PostMeta tags={tags} />`
  (dates already shown separately, so pass only `tags` or a tags-only variant)
  or add a small linked tag row to `EssayLayout`/`ProjectLayout`. Confirm the
  desired placement so it fits each layout's typographic voice.

**5. Verification**

- `bun run build` and confirm `/tags/`, `/tags/<each-tag>/` are emitted and the
  AI-usage tags produce no route. Spot-check that tag links resolve.
